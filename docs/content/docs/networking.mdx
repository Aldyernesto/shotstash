title: Networking
description: Reach Shotstash from outside your LAN with HTTPS through a reverse proxy, Tailscale or Cloudflare Tunnel.

Shotstash listens on plain HTTP on one port (`SHOTSTASH_PORT`, default 3005) and never terminates TLS itself. For anything beyond your LAN, put something in front of it that does: a reverse proxy, Tailscale or Cloudflare Tunnel. Two settings tell the app about it.

## The two settings

| Variable | Set it to | Why |
| --- | --- | --- |
| `APP_URL` | the public address people open, for example `https://media.example.com` | emails and share links are built from it |
| `TRUST_PROXY` | `true`, **only** when the app is reachable exclusively through the proxy | the app then reads the client IP and the scheme from forwarded headers |

With `TRUST_PROXY=true` the app reads `cf-connecting-ip`, then `x-forwarded-for`, for the client IP (rate limits, logs), and `x-forwarded-proto` for the scheme. The scheme decides whether session cookies get the `Secure` flag and whether `Strict-Transport-Security` is sent. If the app port is also reachable directly, anyone could send those headers themselves, so keep `TRUST_PROXY=false` unless the proxy is the only way in.

Bind the published port to the loopback address when the proxy runs on the same machine, so the app is not reachable around it. In `docker-compose.yml`:

```yaml
    ports:
      - "127.0.0.1:${SHOTSTASH_PORT:-3005}:3005"
```

### Checking the scheme: `schemeMismatch`

`GET /api/health` reports `schemeMismatch: true` when `APP_URL` says `https` but requests arrive as `http` (or the other way round). The detailed body is shown to a client on the server itself and to a super admin session:

```bash
docker compose exec app node -e "fetch('http://127.0.0.1:3005/api/health').then(r=>r.json()).then(console.log)"
```

A mismatch behind a proxy usually means the proxy does not send `X-Forwarded-Proto`, or `TRUST_PROXY` is not `true`.

## What the proxy must allow

- **WebSockets** on `/api/graphql` (live job progress, discussion and notifications).
- **Large request bodies.** Uploads are sent in parts of 16 MiB (larger parts only for files above about 160 GB), and a processing worker uploads its whole output in one request. Do not cap the body size below that, and do not buffer requests to disk.
- **Long requests.** Downloads and ZIP archives stream for as long as they take.

## Caddy

Caddy gets and renews certificates by itself and forwards WebSockets and the `X-Forwarded-*` headers by default.

```text
media.example.com {
	reverse_proxy 127.0.0.1:3005 {
		flush_interval -1
	}
}
```

Then in `.env`:

```bash
APP_URL=https://media.example.com
TRUST_PROXY=true
```

## nginx

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name media.example.com;

    ssl_certificate     /etc/letsencrypt/live/media.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/media.example.com/privkey.pem;

    # Upload parts and worker outputs: no size cap, no buffering.
    client_max_body_size 0;
    proxy_request_buffering off;
    proxy_buffering off;
    proxy_read_timeout 1h;
    proxy_send_timeout 1h;

    location / {
        proxy_pass http://127.0.0.1:3005;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # WebSockets for /api/graphql
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
    }
}

# In the http block:
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
```

Use the same two `.env` lines as with Caddy.

## Tailscale

Tailscale gives every device on your tailnet a private address, so you can reach Shotstash from anywhere without opening a port.

- **Private, HTTP:** install Tailscale on the server and open `http://<machine-name>:3005` from your devices. Set `APP_URL=http://<machine-name>:3005` (the MagicDNS name) and leave `TRUST_PROXY=false`, since nothing sits in front of the app.
- **Private, HTTPS:** `tailscale serve --bg 3005` publishes the app at `https://<machine-name>.<tailnet>.ts.net` with a certificate. Set `APP_URL` to that address and `TRUST_PROXY=true`, and bind the app port to `127.0.0.1` as shown above so it is reachable only through `tailscale serve`.

Share links only work for people on your tailnet. To hand links to clients outside it, use a reverse proxy or a tunnel instead (Tailscale Funnel also works and follows the HTTPS setup above).

## Cloudflare Tunnel

A tunnel publishes the app on your domain without opening a port: `cloudflared` makes an outgoing connection and Cloudflare forwards requests through it.

```bash
cloudflared tunnel create shotstash
cloudflared tunnel route dns shotstash media.example.com
```

`~/.cloudflared/config.yml`:

```yaml
tunnel: shotstash
credentials-file: /home/you/.cloudflared/<tunnel-id>.json
ingress:
  - hostname: media.example.com
    service: http://127.0.0.1:3005
  - service: http_status:404
```

Then set `APP_URL=https://media.example.com` and `TRUST_PROXY=true` (Cloudflare sends `cf-connecting-ip` and `x-forwarded-proto`), and bind the app port to `127.0.0.1`.

Limits to know:

- Cloudflare limits a request body by plan (100 MB on the free plan). Upload parts stay well below it, but a processing worker that sends its output through the tunnel can exceed it: run workers on the same network as the app (the bundled `worker` service talks to `http://app:3005` directly).
- WebSockets work through tunnels without extra settings.

## Checklist

1. `APP_URL` is the address people open, with the right scheme.
2. `TRUST_PROXY=true` only when the proxy is the only way in, and the app port is bound to `127.0.0.1` (or firewalled).
3. `/api/health` shows `schemeMismatch: false`.
4. A share link opened on another device works, and live job progress updates without a reload (WebSockets pass).
