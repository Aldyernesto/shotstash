# Posting schedule

One maintainer has to answer every question, review every first issue and fix what breaks. So the posts are spread over two weeks, one big audience at a time, with quiet days in between to fix what the previous wave found.

Day 0 is launch day: every item in [checklist.md](checklist.md) up to "Posts" is done (release out, images public, demo live, README demo link in).

| Day | When | What | Notes |
| --- | --- | --- | --- |
| 0 | any time | Release v0.2.0, demo live, README updated | No posts yet. Watch CI, the demo and the image pulls for a day. |
| 1 | Tuesday or Wednesday, 08:00 to 10:00 US Eastern | Show HN ([show-hn.md](show-hn.md)) | Clear the next six hours. Answer every comment. |
| 2 to 4 | | Fix and reply | Triage issues from HN, ship a patch release if needed, update the docs where people got stuck. |
| 5 | Saturday or Sunday morning US Eastern | r/selfhosted ([reddit-selfhosted.md](reddit-selfhosted.md)) | Never the same day as Show HN. Check the subreddit rules and flair on the day. |
| 6 to 9 | | Fix and reply | Same as above. Note recurring questions for the README and the docs FAQ. |
| 10 | Tuesday to Thursday, 00:01 Pacific | Product Hunt, optional ([product-hunt.md](product-hunt.md)) | Skip it if the issue queue is still busy. |
| 11 to 14 | | Wrap up | Count stars, issues and demo traffic. Write down what to change before the next push. |
| first release + 4 months | | awesome-selfhosted pull request ([awesome-selfhosted.md](awesome-selfhosted.md)) | Not earlier: the list requires a first release older than four months. Date: `<date>`. |

Rules of thumb:

- If a post takes off, delay the next one rather than stack two spikes.
- If the demo goes down, fix it before answering anything else and say so in the thread.
- Never repost the same text to the same place; a follow-up post needs real news (a release, a new worker).
